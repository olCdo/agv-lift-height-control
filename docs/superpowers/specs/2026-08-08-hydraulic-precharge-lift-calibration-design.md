# 液压预充压起升标定设计

## 背景与实测证据

现场从最低位 `raw=2` 开始，以 40% PWM 执行三次约 100 ms 起升脉冲，得到：

| 次数 | 通电时间 | 通电位移 | 观察期总位移 | 峰值电流 |
| --- | ---: | ---: | ---: | ---: |
| 1 | 102.1 ms | 0.000 mm | 0.000 mm | 903 |
| 2 | 107.8 ms | 0.000 mm | 3.174 mm | 837 |
| 3 | 106.7 ms | 0.000 mm | 4.834 mm | 963 |

传感器和 CAN 反馈在这次运行中有效。三次通电窗口内都没有可测位移，第二、
三次的运动主要发生在全零观察阶段；第一次完全没有动作，符合最低位冷启动时
先建立油压、消除机构间隙的表现。现有程序用“100 ms 通电位移至少 1 mm”判断
成功，因此会拒绝这组实际可起升的数据，并把真实响应延迟错误限制为 100 ms。

## 目标与范围

本次只修正 40% 起升短脉冲标定，不改变 Modbus、CAN 帧、下降标定、软限位、
闭环状态机和手动下降协议。

目标如下：

- 最低位冷启动先执行一次受控预充压，再采集三次有效起升样本。
- 每次动作仍为 40% PWM、100 ms 通电和 700 ms 全零观察，不自动升档。
- 用完整观察周期的最终净位移判断能否可靠起升。
- 在完整周期内测量真实首次运动延迟，并保留停泵后的最坏上滑距离。
- 临时最大高度、死手授权、方向、速度、反馈超时和全零停机门禁保持有效。

非目标：不把平台离地绝对高度写入换算，不延长为 150–300 ms 标定脉冲，也不
允许“三次中只成功两次”。

## 标定时序

新增一次预充压周期，随后才执行三次测量周期：

1. 预充压：40% PWM 通电 100 ms，全零观察 700 ms。
2. 测量 1：40% PWM 通电 100 ms，全零观察 700 ms。
3. 测量 2：40% PWM 通电 100 ms，全零观察 700 ms。
4. 测量 3：40% PWM 通电 100 ms，全零观察 700 ms。

操作者每个周期只需按一次 `u`，共四次。只有通电阶段需要 700 ms 死手租约；
进入观察阶段后松开 `u` 不取消已完成的脉冲。一个周期结束后必须重新收到按键
事件，程序不得借用上一次授权自动开始下一周期。

预充压周期不生成 `LiftTrial`，不参与三次一致性判断，也不要求产生位移。它仍
受完整安全门禁约束并保留在 CSV 周期日志中。预充压若出现反向运动、速度异常、
传感器或 CAN 超时、控制循环超时、泵故障或越过临时上限，标定立即失败并归零。

## 测量语义

每个正式测量周期记录以下高度：

- `start_height_mm`：收到本次授权并开始通电时的高度。
- `stop_height_mm`：100 ms 边界首次切换全零时的高度。
- `highest_settle_height_mm`：从停泵到 800 ms 周期结束的最高高度。
- `final_height_mm`：800 ms 周期结束时的最新有效高度。
- `first_movement_at`：从周期开始后，首次正向位移达到 0.1 mm 的采样时刻；搜索
  范围覆盖通电和观察阶段。

`LiftTrial` 字段采用以下定义：

- `displacement_mm = final_height_mm - start_height_mm`，表示观察结束后仍保留的净
  起升量。
- `speed_mm_s = max(0, displacement_mm) / 0.1`，表示每秒等效通电剂量产生的净
  位移，只用于记录，不声称是机构瞬时速度。
- `coast_mm = max(0, highest_settle_height_mm - stop_height_mm)`，表示发出全零后仍
  可能发生的最大上滑；即使运动全部发生在停泵后也必须计入。
- `start_delay_s = first_movement_at - cycle_started_at`，不再截断到 100 ms。
- `peak_current_raw` 仍只统计 100 ms 通电阶段的有符号电流幅值峰值。

方向一致性覆盖完整 800 ms 周期：任一样本低于起点超过既有方向容差即失败。
运行时已有的 1.2 m/s 高度变化速度门禁继续覆盖预充压和测量阶段。

## 通过条件与闭环参数

三次正式 `LiftTrial` 必须全部满足：

- PWM 为 40%，序号严格为 1、2、3。
- 完整周期方向一致。
- `displacement_mm >= 1.0`。
- 已观察到至少 0.1 mm 正向运动。
- `start_delay_s <= 0.3`；超过闭环允许的最大脉冲时间时拒绝保存，不能静默截断。

成功后仍生成单档标定：`min_stable_pwm=40`、`coarse_pwm=40`。摘要参数为：

- `response_delay_s`：三次 `start_delay_s` 的最大值。
- `max_coast_mm`：三次 `coast_mm` 的最大值。
- 40% 电流峰值：三次正式测量通电峰值的最大值。

控制器继续把 `response_delay_s` 限制到 100–300 ms 生成末端通电脉冲，把
`response_delay_s + stable_time_s` 限制到 300–1000 ms 生成等待时间。由于标定
已经拒绝大于 300 ms 的响应，不会把不可支持的延迟伪装为 300 ms。

## 持久化兼容性

起升草稿 schema 从 v2 升到 v3。v1 的 27 次旧草稿和 v2 的“通电位移”草稿都
明确拒绝，提示重新执行起升标定。原因是 `displacement_mm` 和
`start_delay_s` 的语义已经改变，静默迁移会混合两种不可比较的数据。

最终 `calibration.json` 的字段结构不变；它只保存分析后的摘要。新起升草稿会
产生新的标定指纹，因此任何绑定旧起升草稿的下降草稿都会按现有指纹门禁拒绝，
避免组合不同版本的现场结果。

## 现场交互与日志

命令仍为：

```bash
python -m agv_lift_height_control \
  --config config/local.json \
  calibrate-lift --temporary-max-mm 200
```

README 明确说明总共按四次 `u`：第一次预充压，后三次采样；不要长按或连续敲击。
CSV 继续记录每个控制周期、实际/期望命令、授权和反馈，因此预充压动作可以追溯。
标定失败不保存起升草稿，原始 CSV 仍保留。

## 测试门禁

实现必须新增或更新以下测试：

- 最低位预充压允许零位移，且不进入 `LiftCalibrationResult.trials`。
- 总共只产生四个 40% 脉冲，每个不超过 100 ms，周期之间必须重新授权。
- 三次正式样本可在停泵后才开始运动，并以观察结束净位移通过。
- 正式样本任一次最终净位移不足 1 mm、反向或无运动均失败。
- 首次运动延迟在完整 800 ms 内采集；大于 300 ms时失败而非截断。
- `coast_mm` 包含全零命令后出现的全部正向上滑。
- 预充压期间的方向、速度、反馈、循环超时和临时上限故障均立即归零。
- 起升草稿 v3 可以严格往返；v1、v2 和未知字段均拒绝。
- 单档闭环仍不发出超过 40% 的起升命令，末端脉冲时长使用新响应延迟。
- 全量 pytest、`compileall` 和 `git diff --check` 通过。

## 现场验收顺序

更新 Orange Pi 后先运行 pytest，再从最低位执行一次起升标定。操作者在设备旁并
可立即物理断电，临时最大高度保持 200 mm。四次按键结束后先检查屏幕是否成功，
再解析最新 CSV，确认预充压和三次样本的通电时间、最终净位移、响应延迟、上滑
距离及峰值电流。起升草稿成功保存后，才进入下降标定；本次修改不直接开始自动
定高。
