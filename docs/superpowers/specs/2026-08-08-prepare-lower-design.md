# 下降标定前安全预升模式设计

## 1. 背景与目标

起升标定已经生成有效的 schema 3 草稿，现场数据为：最低稳定起升 PWM 40%、最大响应延迟 184.0 ms、最大停泵上滑 4.297 mm、40% PWM 峰值电流 1112。当前设备无法通过独立手动控制预先起升，而下降标定需要依次测试 `0x10` 至 `0xA0` 共十档下降阀值；约 9 mm 的现有行程不足以获得可靠结果。

本功能新增 `prepare-lower` 前台模式，把传感器高度安全地预升到 100 mm，为随后执行下降标定留出行程。该模式不是闭环定高功能，不生成新标定结果，也不得覆盖现有起升草稿。

## 2. 命令行接口

现场命令为：

```bash
python -m agv_lift_height_control \
  --config config/local.json \
  prepare-lower \
  --target-mm 100 \
  --temporary-max-mm 200
```

参数要求：

- `--target-mm` 必填，单位 mm，必须大于启动时的有效传感器高度。
- `--temporary-max-mm` 必填，单位 mm，必须大于或等于目标高度。
- 有效硬上限取临时上限、持久软限位（若存在）、配置绝对上限和 2900 mm 的最小值。
- 目标高度必须低于有效硬上限，并为已测最大停泵上滑保留安全空间，即 `target_mm + max_coast_mm <= effective_max_mm`。

本次现场预期参数为目标 100 mm、临时上限 200 mm。

## 3. 架构与调用链

沿用现有前台运行、传感器线程和 CAN 泵安全发送线程，不新增第二套硬件驱动：

```text
CLI prepare-lower
  -> application.run_application() 校验起升草稿与参数
  -> PrepareLowerSession.step() 推进脉冲、观察和完成状态
  -> ForegroundRuntime.run() 合并SSH授权与通用故障门禁
  -> CanPump.update_command() 更新期望命令
  -> CanPump发送线程每50 ms发送0x217，并解析0x197
```

`PrepareLowerSession` 是独立的有限状态会话，只依赖公共的 `HeightSample`、`PumpFeedback` 和 `PumpCommand`，不得直接依赖 Modbus RTU 实现。未来传感器切换到 Modbus TCP 时不修改本会话。

## 4. 状态与控制行为

会话包含以下状态：

1. `WAIT_AUTH`：输出全零，等待有效的起升授权。
2. `PULSE`：固定输出40%起升 PWM，单次通电100 ms。
3. `SETTLE`：输出全零并观察700 ms，让延迟响应和停泵上滑完成。
4. `DONE`：高度达到或超过100 mm，持续输出全零并结束命令。
5. `FAULT`：任一安全门禁触发，锁存原因并持续输出全零。

控制规则：

- 只使用起升草稿记录的最低稳定 PWM；当前为40%。
- 每个完整周期为100 ms起升脉冲加700 ms全零观察。
- 操作者持续输入 `u` 时，每个字符事件把起升授权续期700 ms。授权在脉冲中丢失时立即归零；重新授权后从新的完整脉冲开始，不续接已中断脉冲。
- 高度在任意控制周期达到或超过目标值后立即进入 `DONE`，不再开始新脉冲。
- 由于液压延迟，达到目标后仍可能发生机械上滑。现场已测最大上滑为4.297 mm，因此100 mm目标的预计最终高度不超过约104.297 mm；200 mm有效硬上限仍持续生效。
- 本模式不发送下降阀命令，不提供自动回落，也不尝试精确保持在100 mm。

## 5. 启动、授权与安全门禁

启动顺序沿用现有泵运行时：

- 验证 `can0` 已处于 UP 且波特率为500 kbit/s，程序不修改网络配置。
- 启动前监听300 ms；发现其他发送者正在发送 `0x217` 时拒绝使能。
- 初始5秒发送 NMT 启动帧，同时保持 `0x217` 全零。
- 5秒窗口结束且收到新鲜 `0x197` 反馈后，才允许进入 `PULSE`。

运行中沿用并覆盖以下故障门禁：

- SSH输入 EOF、`SIGHUP`、`SIGTERM`、Ctrl+C或正常退出均撤销授权并归零。
- 高度样本超过100 ms、CAN反馈超过150 ms、位置变化速度超过1.2 m/s、方向反向、控制循环超过100 ms时进入故障。
- 高度达到有效硬上限时进入故障，不允许再发送非零起升命令。
- 泵故障码非零时进入故障。
- 40% PWM下泵电流超过起升草稿峰值的1.5倍并持续200 ms时进入故障；本次草稿对应阈值为1668 raw。
- CAN命令过期、发送线程异常或停止时持续发送完整全零 `0x217`。

## 6. 数据与持久化边界

- 启动前必须加载并严格校验当前 schema 3 起升草稿。
- 不修改 `lift-calibration-draft.json`。
- 不创建下降草稿，也不创建最终 `calibration.json`。
- CSV继续记录高度、原始值、实际成功发送命令、期望命令、泵反馈、授权事件、状态转换、故障和退出原因。
- TUI模式名称显示为 `prepare-lower`，并显示目标、误差、当前状态、授权剩余时间和安全故障。

## 7. 完成条件与后续操作

成功完成必须同时满足：

- 至少执行过一个完整的起升脉冲；
- 有效传感器高度达到或超过100 mm；
- 未触发任何故障；
- 退出前泵命令已切换为全零。

成功后程序打印最终传感器高度和CSV路径。操作者随后执行：

```bash
python -m agv_lift_height_control \
  --config config/local.json \
  calibrate-lower
```

下降标定仍要求持续按 `d` 授权，并严格执行 `0x10` 至 `0xA0` 十档测试。

## 8. 测试设计

自动测试覆盖：

- CLI要求两个必填高度参数并拒绝非有限值、反向范围和不足的上滑余量。
- 无有效schema 3起升草稿时，在创建串口或CAN对象之前拒绝启动。
- 5秒NMT安全窗口内始终输出全零。
- 无 `u` 授权时保持全零；授权后输出40%且单次不超过100 ms。
- 脉冲结束后保持700 ms全零观察；授权中断立即归零，恢复后重新开始完整脉冲。
- 达到100 mm后不再发送非零命令，成功退出且不覆盖起升草稿。
- 临时上限、持久软限位、配置绝对上限和2900 mm保护均取最严格值。
- 传感器/CAN超时、速度异常、反向运动、控制循环超时、泵故障和持续过流均锁存故障并归零。
- CSV和TUI区分实际命令、期望命令和归零请求。
- 全量pytest、`compileall`和`git diff --check`通过。

现场验证顺序为：

1. 更新代码并运行pytest。
2. 只读监视初始高度。
3. 执行 `prepare-lower --target-mm 100 --temporary-max-mm 200`。
4. 操作者在设备旁持续按 `u`，观察每次短脉冲和停泵上滑。
5. 高度达到目标后确认机构停止且CAN输出归零。
6. 保存CSV并开始下降标定。

## 9. 明确不在本次范围内的内容

- 不实现Modbus TCP传感器；只保持公共高度源接口兼容。
- 不实现自动下降或100 mm闭环保持。
- 不改变40%起升标定结果，不重新估算比例系数。
- 不修改系统CAN网络配置，不终止其他进程。
- 不增加后台服务、`tmux`或`nohup`运行方式。
