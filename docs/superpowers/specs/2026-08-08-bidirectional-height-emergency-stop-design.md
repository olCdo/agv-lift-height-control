# 双向定高与锁存急停设计

## 1. 目标

在现有自动起升闭环基础上增加自动下降定高，并提供可由上层程序直接调用的锁存急停接口。控制入口只接收目标高度，控制器依据当前高度自动选择起升或下降，不再要求 `move` 模式持续读取 `u` 或 `d` 按键。

本次设计同时为后续迁入 `kinco_duolun` 做边界隔离：闭环算法不依赖 SSH、Modbus RTU、SocketCAN 或具体 HR 地址；车辆程序负责提供高度与泵反馈，并且始终只有一个 CAN ID `0x217` 发送者。

## 2. 已确认范围

- `set_target_height(target_mm)` 只接收一个传感器相对行程目标，单位为 mm。
- 当前高度低于目标时自动起升，高于目标时自动下降。
- `move --target-mm` 是明确的自主运动请求，启动后不再依赖键盘运动授权。
- 不增加 SSH 急停键，也不通过键盘解除急停。
- 提供公共 `emergency_stop(reason)` 与 `clear_emergency_stop()` 函数。
- 急停是控制器最高优先级的全局锁存状态；急停状态下任何路径都不能驱动机构。
- 解除急停后保持全零和无目标，必须重新下发目标才能运动。
- 当前独立程序继续使用 Modbus RTU；Modbus TCP 与新 HR 地址属于后续适配，不写入闭环算法。
- 现有 `manual-lower`、标定和上限测量仍是维护模式，继续保留原死手按键门禁。
- 不再重复已经完成的 80 mm、300 mm 等起升定高现场测试；新增自动下降只安排最小低高度冒烟验证。

## 3. 明确不在本次范围

- 不实现物理 GPIO 急停输入。
- 不以软件急停替代车辆物理急停、硬限位或独立断电。
- 不实现 Modbus TCP 高度源和具体目标寄存器握手。
- 不在本次直接修改 `kinco_duolun.py`。
- 不使用未经确认的 `0x60`～`0xA0` 下降阀值加速。
- 不恢复急停前的旧目标，也不在解除急停后自动续跑。

## 4. 分层与公共接口

### 4.1 闭环核心

`HeightController` 保持无硬件依赖，只接收：

- 当前单调时钟；
- `HeightSample`；
- `PumpFeedback`；
- 当前目标与配置。

控制器只输出完整 `PumpCommand`，不得直接打开串口、CAN、终端或 Modbus 客户端。

### 4.2 上层控制门面

新增可由独立程序和未来车辆程序共同使用的 `LiftHeightControl`：

```python
set_target_height(target_mm: float) -> None
cancel_target() -> None
emergency_stop(reason: str) -> None
clear_emergency_stop() -> None
update(now, sample, feedback) -> PumpCommand
```

职责如下：

- 串行化目标、取消和急停状态变化；
- 拒绝急停状态下的新目标；
- 将每个控制周期交给 `HeightController`；
- 向调用方暴露控制状态、故障原因和目标；
- 不拥有 CAN 线程或高度源。

公开方法必须线程安全，以便以后从 `kinco_duolun` 的 Modbus 轮询线程调用。

### 4.3 高度源与泵端口

- `HeightSource` 继续提供 `open/read_sample/close`，当前实现为 RTU，未来 TCP 实现使用同一接口。
- `PumpCommand` 是闭环核心与硬件端口之间唯一的命令对象。
- 当前独立程序由 `CanPump` 编码并发送 `0x217`。
- 未来 `kinco_duolun` 由现有保活线程发送当前命令槽，不再启动第二个 SocketCAN 发送线程。

## 5. `kinco_duolun` 集成边界

当前 `kinco_duolun` 保活线程每 50 ms 固定发送全零 `0x217`。后续集成时应将该固定值改为线程安全的泵命令槽：

```text
上层写入目标
→ LiftHeightControl.set_target_height
→ 周期读取高度和 0x197
→ LiftHeightControl.update
→ PumpCommand 命令槽
→ kinco_duolun 现有 50 ms 保活线程
→ 唯一的 0x217
```

车辆适配器使用现有 `node.interface_control`：

- 订阅 `0x197`；
- 使用 `MotorControl._can_lock`；
- 保持 `0x217` 单一所有权；
- 无目标、故障、急停或命令超时时发送严格全零；
- 不把闭环状态机复制进 `kinco_duolun.py` 的 CAN 回调或 Modbus 线程。

后续 Modbus TCP 适配器必须把“新目标写入事件”与“寄存器里保留的旧数值”区分开。推荐使用命令序号或请求/确认握手；每次轮询同一数值不得重复调用 `set_target_height()`。

## 6. 双向状态机

统一误差定义为：

```text
error_mm = target_mm - height_mm
```

新增状态：

- `COARSE_LOWER`：远离目标的连续下降；
- `LOWER_SETTLE`：关闭阀后的强制观察；
- `LOWER_PULSE`：目标附近的下降微脉冲；
- `EMERGENCY_STOP`：全局锁存急停。

基本转移：

```text
error > +2 mm     → 现有自动起升路径
error < -2 mm     → 自动下降路径
abs(error) <= 2 mm → 液压保持，连续 500 ms 后 HOLD
```

设置新目标、取消目标、普通故障或急停都必须清除未完成的起升和下降脉冲相位。自动运动模式不再读取 `lift_authorized` 或 `lower_authorized`；维护模式仍使用原授权门禁。

## 7. 自动下降控制

现场下降标定中，确认阀值 `0x50` 的 150 ms 试验总位移为 2.63671875 mm；更高阀值虽然成功动作，但未被确认用于舒适下降。本次只使用 `lower_comfortable_valve=0x50`。

### 7.1 连续下降

当前高度比目标高 10 mm 以上时：

```python
PumpCommand(interlock=True, lift_pwm=0, lower_valve=0x50)
```

每个周期重新检查样本、反馈、目标和急停。进入末端区时必须先关阀，不能直接衔接下一次脉冲。

### 7.2 末端下降

进入目标上方 10 mm 区域后按以下相位运行：

1. `LOWER_SETTLE`：完整全零等待 700 ms；
2. 重新测量，若仍高于目标 2 mm，则进入 `LOWER_PULSE`；
3. 使用 `0x50` 通阀 50 ms；
4. 重新进入 700 ms 全零观察；
5. 重复至进入目标 ±2 mm。

50 ms 是一个 CAN 发送周期，实机实际通阀时间可能量化为约 50～100 ms，因此控制器必须依据每次等待后的新样本决定下一步，禁止连续拼接微脉冲。

### 7.3 参数可扩展性

为避免把当前车辆试验值散落在状态机中，控制配置新增有默认值的可选字段：

- `lower_terminal_zone_mm=10.0`；
- `lower_pulse_on_s=0.05`；
- `lower_pulse_wait_s=0.70`。

旧 `local.json` 缺少这些字段时使用默认值；未知字段仍拒绝。下降阀值继续来自最终标定文件，不在配置中重复保存。

### 7.4 下冲与反向

- 下降动作穿过目标但不超过 2 mm时可以进入保持。
- 当前下降接近过程下冲超过 2 mm时停止并判本次失败，不立即反向起升。
- 当前下降接近过程下冲超过 5 mm时锁存控制故障。
- 成功进入 `HOLD` 后清除本次接近方向。以后因自然漂移离开容差带时，可以按所在方向开始一轮新的起升或下降修正。
- 任何命令都必须满足起升 PWM 与下降阀不能同时非零。

## 8. 锁存急停状态

### 8.1 触发

`emergency_stop(reason)` 可从任意线程调用，重复调用幂等。第一次触发必须原子地：

- 进入 `EMERGENCY_STOP`；
- 保存原因和触发时间；
- 丢弃目标、手动请求和所有脉冲相位；
- 将泵命令槽覆盖为 `PumpCommand.safe_stop()`；
- 使 CAN 发送层在后续每个周期都强制选择全零。

急停优先级高于目标、维护模式、标定会话、故障清除和普通命令。急停状态下所有运动请求都拒绝，不能暂存到解除后执行。

CAN发送层独立检查急停锁，因此即使应用控制循环阻塞，也应在最多一个 50 ms 发送周期内切换为：

```text
217#0000000000000000
```

这是软件时延目标，不构成功能安全认证，也不替代硬接线急停。

### 8.2 解除

`clear_emergency_stop()` 只有在以下条件全部满足时才成功：

- 最后成功发送的实际命令为严格全零；
- CAN发送线程没有异常；
- 高度样本有效且新鲜；
- `0x197` 反馈有效、新鲜且故障码为零；
- 当前没有维护模式或标定会话占用命令源。

任一条件不满足都继续保持 `EMERGENCY_STOP` 并返回明确原因。

解除成功后进入无目标的 `MONITOR/IDLE`，命令仍为全零。急停前目标永久丢弃，调用方必须在解除后重新调用 `set_target_height()`。即使新目标数值与旧目标相同，也必须是一条解除后的新请求。

## 9. 其他安全与异常处理

现有保护继续生效：

- 高度样本超过 100 ms；
- `0x197` 超过 150 ms或故障码非零；
- 控制循环超过 100 ms；
- 命令超过 150 ms未刷新；
- 位置变化速度超过 1.2 m/s；
- 方向异常；
- 软上限、配置绝对上限或 2900 mm绝对保护越界；
- CAN/串口/线程异常；
- `q`、Ctrl+C、信号、EOF和正常退出。

自动下降新增方向保护：下降阀非零期间，高度持续反向上升超过现有方向容差时锁存故障。当前没有可靠的下降过流标定阈值，不能用猜测值增加下降电流停机逻辑；继续依赖 `0x197` 故障码、反馈新鲜度和方向监控。

## 10. 日志与界面

- CSV继续分别记录期望命令和最后成功发送的实际命令。
- 新增急停状态、原因、触发时间、清除请求和清除结果字段或事件。
- TUI显示 `coarse_lower/lower_settle/lower_pulse/emergency_stop`。
- `move` 模式不再提示 `u/d` 操作，只保留安全退出说明；不得增加 SSH 急停或急停清除键。
- 维护模式继续显示其原有按键说明。

## 11. 自动化验证

### 11.1 控制器测试

- 目标低于当前高度时进入连续下降；
- 10 mm切区后先全零等待，再发 50 ms脉冲；
- 每次脉冲后必须等待 700 ms；
- 进入 ±2 mm并稳定 500 ms后进入 `HOLD`；
- 2 mm下冲判失败，5 mm下冲锁存故障；
- 目标中途改变会丢弃旧下降相位；
- 任何周期都不允许 PWM和下降阀同时非零；
- 成功 Hold后的双向漂移可以开始新的修正。

### 11.2 急停测试

- 任意自动、维护和外部模式触发急停都进入 `EMERGENCY_STOP`；
- 急停时设置目标、人工下降或标定命令均被拒绝；
- 控制循环不再推进时，CAN门禁仍在一个发送周期内输出全零；
- 重复急停不覆盖第一次原因；
- 不健康条件下解除失败；
- 解除后保持全零，旧目标不恢复；
- 同值目标只有在解除后重新下发才生效。

### 11.3 应用与回归测试

- `move` 不依赖 `u/d` 即可推进自主控制；
- `manual-lower`、起升/下降标定和上限测量仍需要原授权；
- SSH断开、信号、EOF、循环超时和CAN冲突测试不回归；
- 仿真加入下降阀死区、响应延迟和停阀后滑行；
- 现有起升仿真与已验证的末端微脉冲行为保持通过。

## 12. 最小现场验证与交付边界

自动化测试通过后，只安排一次有人监护的低高度自动下降冒烟测试：从已确认安全高度下降到更低的非零目标，确认连续下降、末端脉冲、目标范围和全零退出。已有起升定高测试不重复。

独立测试程序没有外部进程内函数调用通道，因此公共急停函数的实机触发将在后续接入 `kinco_duolun` 调用链时验证；当前阶段通过线程级自动化测试证明状态和CAN门禁行为。未完成该实机调用前，交付说明必须标记“软件急停代码已验证，车辆上层触发链未验证”。

## 13. 验收标准

- 直接给目标高度即可自主选择起升或下降；
- 自动下降只使用确认阀值 `0x50`；
- 近目标采用强制等待和微脉冲；
- 目标容差、稳定时间和下冲保护符合设计；
- 急停是不可运动的锁存状态；
- 解除急停后不会恢复旧目标；
- 独立程序与未来 `kinco_duolun` 均保持 `0x217` 单一发送者；
- Modbus RTU/TCP与CAN传输细节不进入闭环核心；
- 自动化测试、编译检查和Git差异检查通过；
- 未进行的实机验证在交付中明确列出。
