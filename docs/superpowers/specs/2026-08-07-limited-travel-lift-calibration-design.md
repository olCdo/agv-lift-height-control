# 有限行程起升标定与 SSH 非阻塞显示设计

## 背景

Orange Pi 现场测试确认，BRT38 传感器继续按相对最低位的升降行程使用，换算保持为
`raw × 200 / 4096`，不加入平台最低离地 96.5 mm 的绝对高度偏置。

现有起升标定强制执行 40%～80% 共九档、每档三次的 27 次试验。现场临时上限为
200 mm，而 40% PWM、300 ms 通电时单次会产生约 9～13 mm 通电位移及约 5～7 mm
停泵上滑，因此一段行程无法完成 27 次试验。现有状态机还会在 700 ms 全零观察阶段
因死手授权到期而丢弃已完成的脉冲，造成同一 40% 试次重复执行。SSH TUI 曾阻塞主
循环约 2.78 秒，虽然 CAN 独立发送线程按命令超时安全归零，但标定因此失败。

## 目标

- 第一版仅使用已经验证能起升的 40% PWM。
- 每次标定脉冲由 300 ms 缩短为 100 ms。
- 连续三次有效试验后完成起升标定，不再测试 45%～80%。
- 死手授权只允许非零动作；全零观察阶段不因授权到期丢失有效数据。
- SSH 输出拥塞不得阻塞 20 ms 控制循环。
- 保持临时上限、CAN/传感器新鲜度、速度、方向、故障码和退出归零门禁不变。
- 成功生成的标定结果能够进入下降标定和后续低高度闭环定高。

## 非目标

- 本次不加入 80% 粗升，也不采集 45%～80% 中间档数据。
- 本次不修改 Modbus RTU 地址、比例、字序或传感器零点。
- 本次不修改下降标定阀值范围与 150 ms 死手授权。
- 本次不放宽 ±2 mm 稳定误差或 5 mm 最大超调要求。
- 本次不配置后台服务、tmux、nohup 或自动部署。

## 方案比较

### 方案一：固定 40% 与 100 ms，三次后结束（采用）

该方案动作最少、所需行程最短，并且闭环只会发送具备实测电流和滑行数据的 40%
PWM。代价是远距离起升速度较慢。

### 方案二：40% 下自适应增加脉冲时长

从 100 ms 逐步增加至 300 ms 能适配更长启动延迟，但动作次数和累计行程不可预测，
不适合当前 200 mm 现场上限。

### 方案三：完整 PWM 矩阵分批恢复

该方案能够保留分段 P 控制和高速粗升，但需要安全下降复位、跨运行草稿和更多实机
动作，不作为第一版定高门禁。

## 起升标定状态机

每次有效试验按以下顺序执行：

```text
等待 u 授权
  → 40% PWM 通电 100 ms
  → 全零观察 700 ms
  → 完成本次记录
  → 未满三次则重新等待 u 授权
  → 三次均成功后结束并保存起升草稿
```

状态规则：

1. 空闲时没有起升授权，输出完整全零，不创建试次。
2. 100 ms 通电阶段授权失效，立即输出完整全零并丢弃当前不完整试次。
3. 进入全零观察后，授权失效不再删除试次；会话继续检查样本和反馈并完成 700 ms
   观察。
4. 观察结束后若没有新授权，保持全零并等待，不自动开始下一次动作。
5. 三次试验均要求通电阶段位移至少 1 mm，且通电期间方向一致。
6. 40% 不满足三次稳定条件时，本次标定安全失败，不自动提高 PWM。
7. 任一输入门禁失败时锁存失败、输出全零，并禁止保存起升草稿。

`LiftTrial.displacement_mm` 改为 100 ms 通电阶段的位移，即停泵瞬间高度减去起始
高度。`speed_mm_s` 使用同一通电位移除以 0.1 秒。`coast_mm` 继续表示停泵后 700 ms
内高于停泵瞬间高度的最大正向滑行量。泵电流记录 100 ms 通电阶段的绝对峰值。

## 标定结果与控制器

成功结果固定为：

- `min_stable_pwm = 40`
- `coarse_pwm = 40`
- `peak_current_by_pwm` 至少包含实际会被控制器发送的 40% 档
- `response_delay_s` 为三次试验中最大启动延迟，范围 0～0.1 秒
- `max_coast_mm` 为三次试验中最大正向滑行距离

标定模型允许 `coarse_pwm == min_stable_pwm`。峰值电流映射必须覆盖最小稳定 PWM
至粗升 PWM 之间所有实际可发送的 5% 档；旧的完整映射仍可读取，但新草稿不伪造
未实测的 45%～80% 电流。

闭环所有起升状态只发送 40%：粗升区使用连续 40%，中间区退化为 40%，末端区使用
40% 短脉冲。达到或超过目标后仍立即全零，禁止自动下降。若 100 ms 最短脉冲仍造成
超过 5 mm 的超调，本次实机试验失败，不能通过放宽门限掩盖。

## SSH TUI 与控制循环

控制循环继续按 20 ms 运行，CAN 发送线程继续每 50 ms 发送完整 `0x217`。

TUI 只需约 5 Hz 刷新。POSIX 前台终端打开后将 stdout 文件描述符切换为非阻塞，
每帧以完整 ANSI 画面尽力写出。若 SSH PTY 暂时不可写或仅完成部分写入，本帧剩余
内容直接丢弃，下一帧从左上角重新绘制完整画面。终端关闭前恢复 stdout 原阻塞模式
和 termios 属性。

非阻塞显示不能代替控制循环超时门禁。主循环相邻动作周期超过 100 ms 时仍锁存故障、
撤销授权并请求 CAN 全零。

## 数据与持久化

- CSV 从程序启动起逐周期刷新；标定失败、`q`、Ctrl+C 或信号退出后仍保留。
- 三次完整试验全部成功并通过分析后，才原子写入
  `lift-calibration-draft.json`。
- 不保存不完整的起升草稿；由于新流程只有三次动作，失败后重做的行程代价受控。
- 已有旧版 27 次草稿若存在，必须通过明确的版本和严格字段校验，不能静默误解为新
  三次格式。

## 错误处理

- 100 ms 动作期撤权：丢弃本次，保持会话可重试。
- 700 ms 观察期撤权：完成记录，随后等待下一次授权。
- 40% 三次未全部达到 1 mm：标定失败，不保存草稿。
- 临时上限、方向、速度、样本/反馈超时、CAN 故障或控制循环超时：锁存失败并全零。
- SSH 输出拥塞：丢弃显示帧，不影响控制与 CAN 刷新。
- 退出：恢复终端、停止采样线程、补发全零帧并关闭 CAN。

## 测试设计

自动测试至少覆盖：

1. 40% 下三次 100 ms 动作与 700 ms 观察后完成。
2. 通电阶段授权失效会立即归零并丢弃不完整试次。
3. 观察阶段授权失效仍会完成记录，但不自动开始下一次动作。
4. 成功条件使用通电位移，不被停泵后的回落错误否定。
5. 40% 三次不稳定时明确失败，不升级到其他 PWM。
6. 新结果的 `min_stable_pwm` 与 `coarse_pwm` 均为 40，电流映射只要求覆盖实际发送档。
7. 粗升、中间和末端状态均不会产生 45%～80% 命令。
8. SSH stdout 不可写或发生部分写入时，控制循环仍能继续并维持截止时间。
9. TUI 刷新约 5 Hz，CAN 50 ms 周期和控制 20 ms 周期保持不变。
10. 全量既有测试、编译检查与 Git 差异检查通过。

## 现场验收顺序

1. Orange Pi `git pull --ff-only` 并运行全量 pytest。
2. 再次执行只读高度与被动 CAN 检查。
3. 运行 `calibrate-lift --temporary-max-mm 200`，完成三次 40%/100 ms 标定。
4. 检查起升草稿中的位移、响应延迟、滑行距离和峰值电流。
5. 执行下降标定并由操作者事后确认舒适阀值。
6. 使用低高度目标完成三次闭环定高；确认连续 500 ms 位于 ±2 mm，且超调不超过
   5 mm。

## 完成标准

- 有限行程内完成三次起升标定并生成严格草稿。
- SSH 按键和显示不再造成控制循环超过 100 ms。
- 起升闭环只发送 40% PWM。
- 实机低高度目标连续三次满足 ±2 mm 稳定误差与不超过 5 mm 超调。
- 任何故障、撤权或退出路径均保持完整全零输出。
