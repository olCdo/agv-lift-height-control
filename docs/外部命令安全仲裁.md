# 标定与测量命令的安全边界

首次标定和已有标定结果后的重标定不能使用同一条调用链。首次标定尚未产生 `CalibrationBundle`，因此不存在可供控制器使用的同 PWM 实测峰值电流；禁止伪造标定包或虚构电流阈值。

## 首次起升与下降标定

首次标定只使用 `LiftCalibrationSession` 或 `LowerCalibrationSession` 生成命令，不构造 `HeightController`，也不允许执行 `UpperLimitSurvey`。调用方必须按以下顺序运行：

1. 操作者确认运动方向、机械行程、急停和独立物理断电均可用，并持续在现场监护。
2. 每个周期把同一周期的新鲜高度样本、CAN 反馈和独立授权传给标定会话的 `step()`。
3. 只把该会话返回的不可变 `PumpCommand` 交给 `CanPump.update_command()`。
4. `CanPump` 在实际发送前再次检查命令超时、反馈超时和反馈故障码；任一门禁失败均发送全零。
5. 会话失败后不得重新放行其命令；排除故障后创建新的会话重新开始。

首次标定具备样本/反馈新鲜度、反馈故障码、授权、绝对上限和升降累计反向锁存，以及 `CanPump` 的发送前超时与故障门禁。此阶段明确没有“同 PWM 实测峰值电流”二级保护，因为该数据正是本次标定的产物；软件门禁不能替代操作者监护、急停、驱动器保护和物理断电。

## 已有标定包后的重标定与上限测量

`CalibrationBundle` 已经生成并通过校验后，起升重标定、下降重标定和 `UpperLimitSurvey` 只负责生成期望命令。运行程序必须先让 `HeightController.step_external()` 生成唯一的实际命令，再调用 `CanPump.update_command()`：

1. 用 `HeightController.enter_external_mode()` 进入对应的起升标定、下降标定或上限测量状态。
2. 会话的 `step()` 根据当前样本生成 `desired_command`。
3. 将同一周期的本机时间、高度样本、CAN 反馈、期望命令和两个独立授权传给 `HeightController.step_external()`。
4. 只把 `step_external()` 的返回值传给 `CanPump.update_command()`。
5. 会话结束后调用 `exit_external_mode()`；若控制器已锁存故障，退出外部模式不会清除故障。

外部仲裁与自动控制共用控制循环超时、传感器与 CAN 反馈新鲜度、反馈故障码、起升/下降累计反向、同 PWM 持续过流和上限门禁。起升标定、下降标定和 Survey 只接受各自计划中的离散命令，计划外 PWM 或阀值失败关闭。起升与下降不得同时出现；撤销对应授权时，实际命令立即变为全零。软限位和绝对上限禁止继续起升，但允许在健康反馈和下降授权下人工下降脱离限位。

普通 `HeightController.step()` 在外部模式中始终返回全零，避免普通状态机与标定或测量会话同时拥有命令源。

## 未来并入 `kinco_duolun` 的唯一命令槽

车辆进程必须是 `0x217` 的唯一发送者。当前独立程序由 `CanPump` 的单个 50 ms 发送线程
发送完整帧；未来并入 `kinco_duolun` 后，不得在车辆程序旁边继续运行该线程，也不得再加
第二个“急停线程”或“升降线程”发送 `0x217`。正确集成方式是：

1. 保留车辆现有 `0x217` 周期和总线所有权；
2. 把现在固定发送全零的 keepalive 数据槽替换为仲裁后的完整 `PumpCommand`；
3. 每个周期先经过急停、命令新鲜度、`0x197` 新鲜度/故障和传输故障门禁，再由原发送点发送；
4. 成功发送后回报实际命令；急停期间只有成功发送的完整全零才可作为解除证据；
5. 删除或停用独立测试程序的发送线程，不能依赖启动前 300 ms 冲突预检来容忍双发送者。

这里的“替换”是替换现有固定全零 keepalive 的命令来源，不是新增并行线程。NMT、周期、
完整 8 字节布局和停机全零责任仍归唯一发送点所有。

## 公共门面适配边界

车辆业务层只应适配 `LiftHeightControl` 的四个公共方法：

- `set_target_height(target_mm, temporary_max_height_mm=None)`：接收新目标；急停锁存时拒绝；
- `update(now, sample, feedback)`：每个安全控制周期输入统一样本/反馈，返回双向自主期望命令；
- `emergency_stop(reason)`：安全回路或上层急停先锁最终发送门禁，再撤销全部运动意图；
- `clear_emergency_stop()`：仅在本轮全零发送成功、传输恢复、新鲜健康观测和普通故障检查均通过时解除。

适配器负责把车辆安全输入、目标命令和发送成功/失败事件接到这些语义上，不应绕过门面直接
调用 `HeightController.set_target()`，也不应复制控制状态机。当前仓库只完成了软件接口、
共享锁存和独立 `CanPump` 的单元/仿真验证；车辆上层触发到实车全零的完整链尚未实机验证。

## 未来 Modbus TCP 命令的新写语义

Modbus TCP 若用于下发目标，不能只把一个目标寄存器当作永久有效电平。至少使用单调递增的
命令序列号，或等价的“写目标 + 新写握手”协议：适配器只在观察到新的序列/握手后调用一次
`set_target_height()`，并记录已消费编号。

急停触发时撤销控制器目标，但不回退已消费的命令编号；解除急停也不得重新消费寄存器里仍然
存在的旧值。解除急停后必须由上层产生新的序列/握手并重新下发目标，旧目标不能因解除急停
自动复活。通信重连、进程重启和序列回绕规则必须在适配器协议中明确，并以“无法确认是新命令
就不运动”失败关闭。
